    4. Refactor AppointmentService.completeAppointment signature:
       ```typescript
       async completeAppointment(
         studioId: string,
         appointmentId: string,
         payload?: {
           packageSubscriptionId?: string;
           payment?: ExtendedPaymentParams;
           userRole?: 'owner' | 'professional';
         },
       ): Promise<{ appointment: AppointmentRow; lastSession?: boolean; sessionsRemaining?: number }>
       ```

    5. Implement the branching logic:
       - If payload.packageSubscriptionId:
         a. Call packageSubRepo.deductSession(studioId, subscriptionId)
         b. If null returned, throw UnprocessableError('PACKAGE_UNAVAILABLE')
         c. Get package unit price via packageRepo.getUnitPrice
         d. Call commissionService.calculateAndRecord with paymentAmount = unitPrice, paymentMethod = 'package'
         e. Return { appointment, lastSession: result.status === 'completed', sessionsRemaining: result.sessions_total - result.sessions_used }
       - Else if payload.payment:
         a. Validate discount: if userRole !== 'owner', fetch studio settings max_discount_percentage. Guard: if totalAmount === 0, skip discount validation (cortesia). Otherwise if discountAmount / totalAmount * 100 > max_discount_percentage, throw UnprocessableError('DISCOUNT_EXCEEDS_LIMIT')
         b. For each payment entry in payments array, call paymentRepo.create with discount fields (discount split proportionally or only on first entry)
         c. Calculate total net amount = sum(amounts) - discountAmount
         d. Call commissionService.calculateAndRecord with paymentAmount = totalNetAmount, paymentMethod = primary method
         e. Enqueue financial view refresh
         f. Return { appointment }

    6. Update AppointmentService constructor to accept new dependencies: commissionService, packageSubRepo, packageRepo, studioRepo, financialRefreshQueue. Update server.ts wiring accordingly.

    Note: Keep backward compatibility — if payload is undefined or has the old PaymentParams shape, handle gracefully. The old payment?: PaymentParams signature should still work for any existing callers (appointment controller currently passes this shape).

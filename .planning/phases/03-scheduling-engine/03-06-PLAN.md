  <action>
  Create working hours editing screen accessible from Mais > Meu horario.

  **Layout:**
  - Weekly grid matching Phase 1 onboarding pattern: 7 rows (one per day of week)
  - Each row: day name (Seg/Ter/.../Dom) + toggle switch (working/not working) + time range
  - When toggle ON: show start time and end time pickers (tap to edit)
  - When toggle OFF: row is greyed out, times hidden
  - Support multiple time ranges per day: below each active day, show "+ Adicionar intervalo" to add a second range (e.g., 09:00-12:00 and 14:00-18:00). Store as array in working_hours JSONB.
  - Pre-fill from current professional's working_hours JSONB field
  - If professional has no override (null), inherit and display studio default hours

  **Data flow:**
  - Load: GET /api/v1/professionals/:id (or current professional from auth context) — extract working_hours
  - Save: PATCH /api/v1/professionals/:id with updated working_hours JSONB
  - Validate before save: end > start for each range, no overlapping ranges on same day
  - "Salvar" button at bottom, disabled until changes detected

  **JSONB format decision (from RESEARCH.md open question #2):**
  Use array format for future flexibility:
  ```json
  {
    "monday": [{"open": "09:00", "close": "18:00"}],
    "tuesday": [{"open": "09:00", "close": "12:00"}, {"open": "14:00", "close": "18:00"}],
    "wednesday": null
  }
  ```
  Null = day off. Array with ranges = working day.

  **Permissions per CONTEXT.md:**
  - Owner can edit any professional's hours (show professional selector at top)
  - Collaborator edits only her own hours (no selector)

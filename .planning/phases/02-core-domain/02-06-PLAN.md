<interfaces>
<!-- API contracts from backend plans -->

Clients API:
```
GET  /api/v1/clients                → { data: ClientRow[], meta: { has_more, next_cursor } }
POST /api/v1/clients                → { data: ClientRow }
GET  /api/v1/clients/:id            → { data: ClientRow + stats }
PATCH /api/v1/clients/:id           → { data: ClientRow }
DELETE /api/v1/clients/:id          → 204 (or 409)
POST /api/v1/clients/:id/data-deletion → 204

ClientRow: { id, studio_id, name, phone, email, birth_date, tags (string[]), notes, last_appointment_at, total_appointments, created_at, updated_at }
Query params: search, tag, inactive_days, cursor, limit
```

Client sub-resources:
```
GET  /api/v1/clients/:id/appointments → { data: AppointmentRow[], meta }
GET  /api/v1/clients/:clientId/anamneses → { data: AnamnesisRow[] }
PUT  /api/v1/clients/:clientId/anamneses/:categoryId → { data: AnamnesisRow }
GET  /api/v1/clients/:clientId/notes → { data: NoteRow[], meta }
POST /api/v1/clients/:clientId/notes → { data: NoteRow }
GET  /api/v1/clients/:clientId/consents → { data: ConsentStatus[] }
POST /api/v1/clients/:clientId/consents → { data: ConsentRecord }
```

       - `updateClient(id, fields)` → PATCH /api/v1/clients/:id
       - `deleteClient(id)` → DELETE /api/v1/clients/:id
       - `listAppointments(clientId, {status, cursor, limit})` → GET /clients/:id/appointments
       - `listAnamneses(clientId)` → GET /clients/:clientId/anamneses
       - `upsertAnamnesis(clientId, categoryId, fields)` → PUT /clients/:clientId/anamneses/:categoryId
       - `listNotes(clientId, {cursor, limit})` → GET /clients/:clientId/notes
       - `createNote(clientId, content)` → POST /clients/:clientId/notes
       - `getConsents(clientId)` → GET /clients/:clientId/consents
       - `recordConsent(clientId, type, action)` → POST /clients/:clientId/consents

       - Header: name, phone, email, tag chips (auto + manual)
       - TabBar with 3 tabs: "Historico" | "Anamnese" | "Notas"
       - Each tab is a focused view, no infinite scroll within tabs (except appointment history which uses pagination)
       - Edit button in header to navigate to ClientFormScreen in edit mode

       **Historico tab:**
       - Lists appointments from GET /clients/:id/appointments
       - Each row: service name, professional name, date, status badge (completed=green, cancelled=red, no_show=orange)
       - Cursor pagination with "Carregar mais" button at bottom
       - Empty state: "Nenhum agendamento ainda"

       **Anamnese tab:**
       - Lists anamnesis records from GET /clients/:clientId/anamneses
       - Each row: category name + "Preenchido em DD/MM/YYYY" or "Nao preenchido"
       - Tap navigates to AnamnesisFormScreen
       - Also show categories without anamnesis (from service_categories API) as "Nao preenchido"

       **Notas tab:**
       - Timeline of notes from GET /clients/:clientId/notes, reverse chronological
       - Each note: author name, date, content text
       - Text input at bottom with send button to add new note
       - Notes are immutable — no edit/delete UI

       **LGPD section (below tabs or in a collapsible section — Claude's discretion):**
       - Marketing consent toggle: "Consentimento WhatsApp Marketing" with Switch widget
       - Toggle ON calls POST /clients/:clientId/consents { type: 'marketing_whatsapp', action: 'granted' }
       - Toggle OFF calls POST /clients/:clientId/consents { type: 'marketing_whatsapp', action: 'revoked' }
       - Current state loaded from GET /clients/:clientId/consents
       - Audit log link or expandable section showing recent audit entries (GET /api/v1/audit-logs?entity_type=client&entity_id=:id)

       **Data deletion:**
       - Button at very bottom: "Excluir dados do cliente (LGPD)" — red, with confirmation dialog
       - Calls POST /clients/:clientId/data-deletion
       - After success, navigates back to client list

    2. **AnamnesisFormScreen** — Dynamic form per service category.
       - Load existing anamnesis (if any) from GET /clients/:clientId/anamneses/:categoryId or from already fetched list
       - Load template fields from AnamnesisTemplates for this category
       - Merge: template fields as base + existing saved values + any custom fields from saved data
       - Render fields dynamically:
         - boolean → SwitchListTile
         - text → TextFormField
         - select → DropdownButtonFormField
       - "Adicionar campo" button at bottom to add custom text field
       - Save button calls PUT /clients/:clientId/anamneses/:categoryId with all fields as JSONB
